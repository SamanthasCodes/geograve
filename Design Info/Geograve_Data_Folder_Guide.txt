2. BIOME GLOBE DATA
------------------------------------------------------------

File:
Data/biomes_simplified.geojson

Purpose:
This file contains simplified biome polygons for the D3 globe background.

D3 can load this directly with:
const biomes = await d3.json("Data/biomes_simplified.geojson");

Each feature has a biome_group property. Use biome_group to color the globe polygons.

Biome colors:
Forest — #2D6A4F
Grassland & Savanna — #8DB048
Desert — #D4956A
Tundra & Ice — #7FB8D4
Wetlands & Coast — #2BBFB0
Ocean — #2E6BA8

Biome color map:
const biomeColors = {
  "Forest": "#2D6A4F",
  "Grassland & Savanna": "#8DB048",
  "Desert": "#D4956A",
  "Tundra & Ice": "#7FB8D4",
  "Wetlands & Coast": "#2BBFB0",
  "Ocean": "#2E6BA8"
};

Important note:
If the GeoJSON still uses "Other" instead of "Ocean", map "Other" to the ocean color:

const biomeColors = {
  "Forest": "#2D6A4F",
  "Grassland & Savanna": "#8DB048",
  "Desert": "#D4956A",
  "Tundra & Ice": "#7FB8D4",
  "Wetlands & Coast": "#2BBFB0",
  "Ocean": "#2E6BA8",
  "Other": "#2E6BA8"
};

Example D3 draw pattern:
svg.selectAll(".biome")
  .data(biomes.features)
  .enter()
  .append("path")
  .attr("class", "biome")
  .attr("d", path)
  .attr("fill", d => biomeColors[d.properties.biome_group] || "#2E6BA8")
  .attr("opacity", 0.75);

The path generator should use the same projection as the globe.

4. WEEKLY ABUNDANCE DATA
------------------------------------------------------------

Files:
Data/Species/{Common Name}/weekly_abundance_27km.json
Data/Species/{Common Name}/weekly_abundance_27km_long.csv

Example:
Data/Species/Barn Swallow/weekly_abundance_27km.json

Purpose:
This file powers the weekly bird abundance/migration animation on the globe.

Source:
eBird Status & Trends weekly abundance raster data, processed from TIFF raster into D3-ready JSON/CSV.

Data structure:
Each row is one abundance point for one species, one week, and one location.

Fields:
speciesCode
commonName
week
lon
lat
abundance

Example JSON row:
{
  "speciesCode": "barswa",
  "commonName": "Barn Swallow",
  "week": 1,
  "lon": -97.5,
  "lat": 29.2,
  "abundance": 0.034
}

How D3 should use it:
When a user selects a species, load that species' weekly JSON file.

Example:
const weeklyData = await d3.json(
  `Data/Species/${commonName}/weekly_abundance_27km.json`
);

Group by week:
const dataByWeek = d3.group(weeklyData, d => +d.week);

Then use the selected week to update the globe points or heat layer:
function updateWeek(week) {
  const points = dataByWeek.get(week) || [];

  svg.selectAll(".abundance-point")
    .data(points, d => `${d.lon},${d.lat}`)
    .join(
      enter => enter.append("circle")
        .attr("class", "abundance-point")
        .attr("r", d => abundanceScale(d.abundance))
        .attr("fill", "#7EC8A0")
        .attr("opacity", 0.65),
      update => update,
      exit => exit.remove()
    )
    .attr("cx", d => projection([+d.lon, +d.lat])?.[0])
    .attr("cy", d => projection([+d.lon, +d.lat])?.[1]);
}

Timeline:
This data is weekly and should support a 52-week animation.

5. REGIONAL STATS DATA
------------------------------------------------------------

File:
Data/Species/{Common Name}/regional_stats.csv

Example:
Data/Species/Barn Swallow/regional_stats.csv

Purpose:
This file powers the Distribution by Region bar chart.

Source:
eBird Status & Trends regional summary data.

How D3 should use it:
When a user selects a species, load the regional stats CSV for that species.

Example:
const regionalStats = await d3.csv(
  `Data/Species/${commonName}/regional_stats.csv`
);

The exact columns may vary slightly depending on eBird output, but the file should provide region-level population/distribution summaries for the selected species.

Use these exact labels in the page, not "Breeding Season" or "Migration Season".

The bar chart title should use:
DISTRIBUTION BY REGION • ALL YEAR
DISTRIBUTION BY REGION • BREEDING
DISTRIBUTION BY REGION • WINTERING
DISTRIBUTION BY REGION • MIGRATION

SEASON LABEL MAPPING FOR REGIONAL STATS

The eBird regional stats file uses these season values:

breeding
nonbreeding
prebreeding_migration
postbreeding_migration

Our webpage should use simpler user-facing labels:

All Year
Breeding
Wintering
Migration

Use this mapping in D3:

All Year = breeding + nonbreeding + prebreeding_migration + postbreeding_migration
Breeding = breeding
Wintering = nonbreeding
Migration = prebreeding_migration + postbreeding_migration

Suggested JS mapping:

const seasonMap = {
  "All Year": ["breeding", "nonbreeding", "prebreeding_migration", "postbreeding_migration"],
  "Breeding": ["breeding"],
  "Wintering": ["nonbreeding"],
  "Migration": ["prebreeding_migration", "postbreeding_migration"]
};

For the Distribution by Region bar chart, filter regional_stats.csv using the selected UI label.

Example:
If the user selects "Breeding", use rows where season == "breeding".
If the user selects "Wintering", use rows where season == "nonbreeding".
If the user selects "Migration", combine rows from both migration seasons:
  prebreeding_migration
  postbreeding_migration

Important note:
For Migration and All Year, multiple eBird seasons are combined. If percentages are summed directly, totals may exceed 100 because the rows represent seasonal summaries. To keep the bar chart readable, group by region, sum the selected seasonal values, then normalize the displayed percentages so the selected category totals to 100%.

Suggested display titles:

DISTRIBUTION BY REGION • ALL YEAR
DISTRIBUTION BY REGION • BREEDING
DISTRIBUTION BY REGION • WINTERING
DISTRIBUTION BY REGION • MIGRATION

Country abbreviations and emojis: - there is a .csv and .json file with emojis, names and abbreviations
Use emoji flags/icons with abbreviated country (use full country name unless too long) or region labels in the bar chart.
